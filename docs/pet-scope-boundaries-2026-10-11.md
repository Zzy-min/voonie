# Vonnie 对话范围判定

范围以用户要求助手执行的动作界定，不以作业、数学、代码等词界定。不要求用户先有日记，也不要求经历陈述必须包含情绪词。

| 当前请求 | 处理 | 回复边界 |
| --- | --- | --- |
| 作业难，能开导我吗 | 情绪支持 | 接住压力，询问感受，不索要题目 |
| 鸡兔同笼，我有自己的解法，但老师说我不对 | 个人经历 | 可以回应努力被否定的失落，不判断解法或老师对错 |
| 为什么老师总否定我 | 情绪反思 | 谈感受与经历，不推断老师真实动机 |
| 我的解法对不对、哪一步错了 | 外部任务 | 不检查解法，引导继续谈感受 |
| 不要答案，只给解题思路 | 外部任务 | 提示和思路同样属于解题 |
| 倾诉之后说“帮我看看” | 模糊指代 | 一个问题澄清需求，未澄清前不解题 |
| 今天学了微积分，想记下来 | 日记记录 | 整理用户提供的经历，不扩展微积分知识 |
| 为日记讲解微积分 | 外部任务 | 日记包装不改变实际任务性质 |
| 我之前和室友吵架了吗 | 个人记录回顾 | 查授权记录；未找到不代表未发生，问句不成为事实 |

每轮重新分类，上轮允许倾诉不代表下一轮可以解题。明确混合外部任务的请求仍按原有规则拒绝；不扩展为通用学习助手。

输入判定 → 授权记忆检索（需要时） → 限定回复生成 → 输出检查 → 返回。输出检查同时约束主动索要题目、代码或解法，以及未经用户确认的事实。分类异常或超时沿用拒绝默认；不把异常当作范围语义验证通过。

截图中的两个问题分别是经历陈述误拒，以及助手主动问“哪道题”将情绪对话引向解题。当前修改统一输入、生成和输出三层规则。

验证使用模拟模型覆盖请求放行/拒绝、模糊意图澄清、越界追问阻断；这验证控制路径与提示词契约，不证明真实模型语义分类可靠。上线验收须重新发送上述多轮案例，观察新回复，旧消息不自动更新。后端部署与小程序开发版上传是两个独立步骤；此文档不作为部署或真机验收回执。
